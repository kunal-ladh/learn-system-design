## 1. The LLD Interview Framework

LLD interviews test whether you can translate a real-world problem into a clean, extensible class model. They care about:

1. **Correct modeling**: identifying the right entities and their relationships
2. **Encapsulation**: hiding implementation details behind interfaces
3. **Extensibility**: new requirements should require minimal changes
4. **Trade-off articulation**: why did you choose composition over inheritance here?

### The 4-Step Approach (45 minutes)

| Step | Time | Action |
|---|---|---|
| **Clarify requirements** | 5 min | Use cases, actors, constraints, what's in/out of scope |
| **Identify core entities** | 5 min | Nouns in the problem → candidate classes |
| **Define relationships & interfaces** | 15 min | Associations, inheritance, interfaces, enums |
| **Implement key flows** | 20 min | Write code for the most important 2–3 scenarios |

### Requirements Clarification Questions

For any LLD problem, ask:
- Who are the actors (users, systems)?
- What are the primary use cases (top 5)?
- What are the constraints (concurrency, scale — though LLD is single-machine)?
- What is explicitly out of scope?
- Do I need to handle concurrency?

## 2. OOP Fundamentals

### The Four Pillars

**Encapsulation**: Bundle data + behavior together. Hide internal state. Expose only what's needed.

```java
// Bad: everything public, anyone can corrupt state
public class BankAccount {
    public double balance;
    public String status;
}

// Good: state is private, behavior controls how state changes
public class BankAccount {
    private double balance;
    private AccountStatus status;

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("Amount must be positive");
        if (status == AccountStatus.FROZEN) throw new IllegalStateException("Account is frozen");
        this.balance += amount;
    }

    public double getBalance() { return balance; }
}
```

**Abstraction**: Expose what a thing does, hide how it does it.

```java
// Users of PaymentGateway don't need to know it calls Razorpay internally
public interface PaymentGateway {
    PaymentResult charge(String customerId, Money amount);
    void refund(String transactionId, Money amount);
}

public class RazorpayGateway implements PaymentGateway { ... }
public class StripeGateway implements PaymentGateway { ... }
```

**Inheritance**: "is-a" relationship. Child gets parent's behavior and can override it.

```java
public abstract class Vehicle {
    protected String licensePlate;
    protected VehicleType type;
    public abstract int getParkingSpotSize(); // every vehicle knows how big it is
}

public class Car extends Vehicle {
    public int getParkingSpotSize() { return 1; }
}

public class Truck extends Vehicle {
    public int getParkingSpotSize() { return 2; }
}
```

**Polymorphism**: Same interface, different behavior at runtime.

```java
// Runtime polymorphism (overriding)
Vehicle v = new Car(...);
v.getParkingSpotSize(); // calls Car's implementation, not Vehicle's

// Compile-time polymorphism (overloading) — same name, different signature
public double calculateFare(int hours) { ... }
public double calculateFare(int hours, VehicleType type) { ... }
```

### Inheritance vs Composition

**Inheritance** (is-a): `Car extends Vehicle` — Car IS a Vehicle.
**Composition** (has-a): `Order has a PaymentProcessor` — Order HAS a payment processor.

**Prefer composition over inheritance**:
```java
// Inheritance problem: rigid hierarchy
class FlyingCar extends Car { ... } // inherits ALL of Car
class FlyingCar extends Airplane { ... } // Java doesn't allow multiple inheritance

// Composition: flexible, mix capabilities
class FlyingCar {
    private CarEngine carEngine;     // has driving capability
    private AircraftEngine jetEngine; // has flying capability
}
```

Inheritance breaks encapsulation (child knows parent's internals). Composition doesn't.

**Rule**: Use inheritance only when the relationship is truly "is-a" and the hierarchy is stable. Use composition for everything else.

### Abstract Classes vs Interfaces

| | Abstract Class | Interface |
|---|---|---|
| Purpose | Partial implementation + force override | Pure contract |
| State | Can have instance variables | No state (Java 8+ has default methods) |
| Constructor | Has constructor | No constructor |
| Multiple | Single inheritance only | Implement many interfaces |
| Use when | Base behavior shared by all subclasses | Define a capability across unrelated classes |

```java
// Abstract class: all animals can eat — share the behavior
public abstract class Animal {
    private String name;
    public void eat(Food food) { this.hunger -= food.getNutrition(); } // shared impl
    public abstract void makeSound(); // must override
}

// Interface: capabilities, not hierarchy — a Dog can be Trainable, a Robot can also be Trainable
public interface Trainable {
    void learn(Command command);
    void perform(Command command);
}
```

## 3. SOLID Principles

SOLID is the foundation of extensible object-oriented design. Every pattern uses at least one SOLID principle.

### S — Single Responsibility Principle

**A class should have one reason to change.**

```java
// Bad: UserService does too much — any change to email or DB forces changes here
public class UserService {
    public User createUser(String name, String email) {
        // validate
        // save to DB
        // send welcome email
        // log to audit trail
    }
}

// Good: each class has one responsibility
public class UserService {
    private final UserRepository userRepository;
    private final EmailService emailService;
    private final AuditLogger auditLogger;

    public User createUser(String name, String email) {
        User user = User.create(name, email);
        userRepository.save(user);
        emailService.sendWelcome(user);
        auditLogger.log("user_created", user.getId());
        return user;
    }
}
// If email template changes → only EmailService changes
// If DB schema changes → only UserRepository changes
```

### O — Open/Closed Principle

**Open for extension, closed for modification. Add new behavior without changing existing code.**

```java
// Bad: adding a new discount type requires modifying calculateDiscount
public double calculateDiscount(Order order, String discountType) {
    if (discountType.equals("SEASONAL")) return order.getTotal() * 0.1;
    if (discountType.equals("EMPLOYEE")) return order.getTotal() * 0.2;
    if (discountType.equals("BULK")) return order.getTotal() * 0.15;
    // to add "LOYALTY" discount → must modify this method
}

// Good: new discount types extend without modifying existing code
public interface DiscountStrategy {
    double calculate(Order order);
}

public class SeasonalDiscount implements DiscountStrategy {
    public double calculate(Order order) { return order.getTotal() * 0.1; }
}

public class EmployeeDiscount implements DiscountStrategy {
    public double calculate(Order order) { return order.getTotal() * 0.2; }
}

// Adding LoyaltyDiscount: new class, zero changes to existing code
public class LoyaltyDiscount implements DiscountStrategy {
    public double calculate(Order order) { return order.getTotal() * 0.25; }
}
```

### L — Liskov Substitution Principle

**Subtypes must be substitutable for their base types without breaking correctness.**

```java
// Bad: Square breaks Rectangle's contract
// Rectangle invariant: you can set width and height independently
public class Rectangle {
    protected int width, height;
    public void setWidth(int w) { this.width = w; }
    public void setHeight(int h) { this.height = h; }
    public int area() { return width * height; }
}

public class Square extends Rectangle {
    @Override
    public void setWidth(int w) { this.width = w; this.height = w; } // breaks contract!
    @Override
    public void setHeight(int h) { this.width = h; this.height = h; }
}

Rectangle r = new Square();
r.setWidth(5);
r.setHeight(3);
r.area(); // expects 15, gets 9 — LSP violated

// Fix: don't extend; use a common interface or treat as separate classes
public interface Shape { int area(); }
public class Rectangle implements Shape { ... }
public class Square implements Shape { ... }
```

LSP in practice: if a subclass throws exceptions the parent doesn't, removes preconditions, or weakens postconditions → LSP violation.

### I — Interface Segregation Principle

**Clients should not be forced to depend on interfaces they don't use.**

```java
// Bad: fat interface forces all implementers to implement all methods
public interface Worker {
    void work();
    void eat();
    void sleep();
}

// Robot can work but doesn't eat or sleep → must implement empty methods or throw
public class Robot implements Worker {
    public void work() { ... }
    public void eat() { throw new UnsupportedOperationException(); } // bad!
    public void sleep() { throw new UnsupportedOperationException(); }
}

// Good: split into focused interfaces
public interface Workable { void work(); }
public interface Eatable   { void eat(); }
public interface Sleepable { void sleep(); }

public class Human implements Workable, Eatable, Sleepable { ... }
public class Robot implements Workable { ... } // only what it needs
```

### D — Dependency Inversion Principle

**High-level modules should not depend on low-level modules. Both should depend on abstractions.**

```java
// Bad: CorporateService (high-level) depends directly on EmailSender (low-level)
public class CorporateService {
    private EmailSender emailSender = new EmailSender(); // concrete dependency!
    // changing to SMS requires modifying CorporateService
}

// Good: depend on abstraction, inject concrete implementation
public interface NotificationService {
    void notify(User user, String message);
}

public class CorporateService {
    private final NotificationService notificationService; // abstraction

    public CorporateService(NotificationService notificationService) {
        this.notificationService = notificationService; // injected
    }
}

// Swap implementations without touching CorporateService
new CorporateService(new EmailNotificationService());
new CorporateService(new SMSNotificationService());
new CorporateService(new PushNotificationService());
```

This is exactly what Spring's `@Autowired` does — dependency injection at runtime.

## 4. Design Patterns — Creational

Creational patterns deal with how objects are created. They hide the creation logic.

### Singleton

**One instance, globally accessible.**

```java
// Thread-safe Singleton (double-checked locking)
public class DatabaseConnection {
    private static volatile DatabaseConnection instance;

    private DatabaseConnection() {} // private constructor prevents direct instantiation

    public static DatabaseConnection getInstance() {
        if (instance == null) {
            synchronized (DatabaseConnection.class) {
                if (instance == null) { // second check — after acquiring lock
                    instance = new DatabaseConnection();
                }
            }
        }
        return instance;
    }
}

// Better: enum-based Singleton (thread-safe by JVM, prevents reflection attacks)
public enum ConfigManager {
    INSTANCE;
    private final Map<String, String> config = new HashMap<>();
    public String get(String key) { return config.get(key); }
}
// Usage: ConfigManager.INSTANCE.get("db.url")
```

**Use when**: Logger, configuration manager, thread pool, connection pool.
**Avoid when**: It becomes a hidden dependency — prefer DI instead.

### Factory Method

**Delegate object creation to subclasses. Caller doesn't know the concrete type.**

```java
public abstract class NotificationFactory {
    public abstract Notification createNotification(String message);

    public void send(User user, String message) {
        Notification n = createNotification(message); // factory method
        n.deliver(user);
    }
}

public class EmailNotificationFactory extends NotificationFactory {
    public Notification createNotification(String message) {
        return new EmailNotification(message);
    }
}

public class SMSNotificationFactory extends NotificationFactory {
    public Notification createNotification(String message) {
        return new SMSNotification(message);
    }
}
```

### Abstract Factory

**Factory of factories. Create families of related objects without specifying concrete classes.**

```java
// Family 1: Light theme UI
// Family 2: Dark theme UI
public interface UIFactory {
    Button createButton();
    TextField createTextField();
    Dialog createDialog();
}

public class LightThemeFactory implements UIFactory {
    public Button createButton() { return new LightButton(); }
    public TextField createTextField() { return new LightTextField(); }
    public Dialog createDialog() { return new LightDialog(); }
}

public class DarkThemeFactory implements UIFactory {
    public Button createButton() { return new DarkButton(); }
    public TextField createTextField() { return new DarkTextField(); }
    public Dialog createDialog() { return new DarkDialog(); }
}

// Client uses factory without knowing which theme is active
public class Application {
    private final UIFactory factory;
    public Application(UIFactory factory) { this.factory = factory; }

    public void buildUI() {
        Button btn = factory.createButton(); // always consistent theme
        Dialog dlg = factory.createDialog();
    }
}
```

### Builder

**Build complex objects step by step. Useful when constructor would have many parameters.**

```java
// Without Builder: 7-argument constructor — confusing, easy to swap args
new Transaction("TXN001", "NEFT", 50000.0, "HDFC", "SBI", "PENDING", ZonedDateTime.now());

// With Builder: readable, optional parameters, immutable result
public class Transaction {
    private final String id;
    private final String type;
    private final double amount;
    private final String fromBankIfsc;
    private final String toBankIfsc;
    private final TransactionStatus status;
    private final ZonedDateTime createdAt;

    private Transaction(Builder builder) {
        this.id = builder.id;
        this.type = builder.type;
        this.amount = builder.amount;
        this.fromBankIfsc = builder.fromBankIfsc;
        this.toBankIfsc = builder.toBankIfsc;
        this.status = builder.status;
        this.createdAt = builder.createdAt;
    }

    public static class Builder {
        private String id;
        private String type;
        private double amount;
        private String fromBankIfsc;
        private String toBankIfsc;
        private TransactionStatus status = TransactionStatus.PENDING; // default
        private ZonedDateTime createdAt = ZonedDateTime.now();        // default

        public Builder id(String id) { this.id = id; return this; }
        public Builder type(String type) { this.type = type; return this; }
        public Builder amount(double amount) { this.amount = amount; return this; }
        public Builder fromBank(String ifsc) { this.fromBankIfsc = ifsc; return this; }
        public Builder toBank(String ifsc) { this.toBankIfsc = ifsc; return this; }
        public Builder status(TransactionStatus s) { this.status = s; return this; }

        public Transaction build() {
            if (id == null || type == null) throw new IllegalStateException("id and type required");
            return new Transaction(this);
        }
    }
}

// Usage: self-documenting
Transaction txn = new Transaction.Builder()
    .id("TXN001")
    .type("NEFT")
    .amount(50000.0)
    .fromBank("HDFC0001234")
    .toBank("SBIN0001234")
    .build();
```

Lombok's `@Builder` generates this automatically. Know the manual version for interviews.

### Prototype

**Clone an existing object instead of creating from scratch. Useful when creation is expensive.**

```java
public interface Cloneable {
    Object clone();
}

public class DocumentTemplate implements Cloneable {
    private String header;
    private String footer;
    private List<Section> sections;

    @Override
    public DocumentTemplate clone() {
        DocumentTemplate copy = new DocumentTemplate();
        copy.header = this.header;
        copy.footer = this.footer;
        copy.sections = new ArrayList<>(this.sections); // deep copy list
        return copy;
    }
}

// Instead of rebuilding template from DB every time:
DocumentTemplate base = templateRepository.load("invoice_template");
DocumentTemplate invoice1 = base.clone();
invoice1.setCustomerName("Niyo Corp");
```

## 5. Design Patterns — Structural

Structural patterns deal with how classes and objects compose to form larger structures.

### Adapter

**Make incompatible interfaces work together. Wrap an existing class with a new interface.**

```java
// Third-party library: KarzaClient (we can't modify)
public class KarzaClient {
    public KarzaIfscResponse fetchIfscDetails(String ifscCode) { ... }
}

// Our system expects this interface
public interface IfscService {
    IfscDetails getIfscDetails(String ifscCode);
}

// Adapter wraps KarzaClient and translates
public class KarzaIfscAdapter implements IfscService {
    private final KarzaClient karzaClient;

    public KarzaIfscAdapter(KarzaClient karzaClient) {
        this.karzaClient = karzaClient;
    }

    @Override
    public IfscDetails getIfscDetails(String ifscCode) {
        KarzaIfscResponse response = karzaClient.fetchIfscDetails(ifscCode);
        // translate KarzaIfscResponse → IfscDetails
        return new IfscDetails(
            response.getBankName(),
            response.getBranchName(),
            response.getCity()
        );
    }
}

// When switching from Karza to Civic: write CivicIfscAdapter, swap injection
// Core business logic never changes
```

### Decorator

**Add behavior to an object dynamically without modifying its class. Wraps the original object.**

```java
public interface DataSource {
    void write(String data);
    String read();
}

public class FileDataSource implements DataSource {
    public void write(String data) { /* write to file */ }
    public String read() { /* read from file */ }
}

// Decorator base
public abstract class DataSourceDecorator implements DataSource {
    protected DataSource wrapped;
    public DataSourceDecorator(DataSource source) { this.wrapped = source; }
}

// Add encryption on top
public class EncryptionDecorator extends DataSourceDecorator {
    public void write(String data) {
        wrapped.write(encrypt(data)); // encrypt, then delegate
    }
    public String read() {
        return decrypt(wrapped.read()); // delegate, then decrypt
    }
}

// Add compression on top of encryption
public class CompressionDecorator extends DataSourceDecorator {
    public void write(String data) {
        wrapped.write(compress(data));
    }
}

// Stack decorators at runtime
DataSource source = new CompressionDecorator(
                        new EncryptionDecorator(
                            new FileDataSource("data.txt")));
source.write("sensitive data"); // compressed + encrypted + written to file
```

Java's `InputStream`/`OutputStream` hierarchy is exactly this pattern:
```java
new BufferedReader(new InputStreamReader(new FileInputStream("file.txt")));
```

### Facade

**Simplify a complex subsystem with a single clean interface. Hide complexity.**

```java
// Complex subsystems
class KycService      { boolean verifyPan(String pan) { ... } }
class BankService     { boolean verifyBank(String account, String ifsc) { ... } }
class AmlService      { boolean screenForBlacklist(String name) { ... } }
class CreditService   { CreditScore getCreditScore(String pan) { ... } }

// Facade: one entry point for "onboard a corporate"
public class CorporateOnboardingFacade {
    private final KycService kycService;
    private final BankService bankService;
    private final AmlService amlService;
    private final CreditService creditService;

    public OnboardingResult onboard(CorporateOnboardingRequest request) {
        if (!kycService.verifyPan(request.getPan())) return OnboardingResult.KYC_FAILED;
        if (!amlService.screenForBlacklist(request.getCompanyName())) return OnboardingResult.AML_FAILED;
        if (!bankService.verifyBank(request.getAccount(), request.getIfsc())) return OnboardingResult.BANK_FAILED;
        CreditScore score = creditService.getCreditScore(request.getPan());
        return OnboardingResult.success(score);
    }
}

// Controller only talks to the facade
corporateOnboardingFacade.onboard(request);
```

### Proxy

**Control access to an object. Intercept calls to add caching, logging, access control, lazy loading.**

```java
// Real service (expensive to call — external API)
public interface IfscLookupService {
    IfscDetails lookup(String ifsc);
}

public class RealIfscLookupService implements IfscLookupService {
    public IfscDetails lookup(String ifsc) { /* calls Civic API */ }
}

// Caching proxy
public class CachingIfscLookupProxy implements IfscLookupService {
    private final IfscLookupService real;
    private final Map<String, IfscDetails> cache = new ConcurrentHashMap<>();

    public CachingIfscLookupProxy(IfscLookupService real) { this.real = real; }

    public IfscDetails lookup(String ifsc) {
        return cache.computeIfAbsent(ifsc, real::lookup); // cache-aside
    }
}

// Client doesn't know if it's talking to real or proxy
IfscLookupService service = new CachingIfscLookupProxy(new RealIfscLookupService());
```

Spring AOP generates runtime proxies for `@Transactional`, `@Cacheable`, `@Async`.

### Composite

**Treat individual objects and groups of objects uniformly. Tree structures.**

```java
// File system: files and directories treated the same way
public interface FileSystemNode {
    String getName();
    long getSize();
    void print(String indent);
}

public class File implements FileSystemNode {
    private String name;
    private long size;
    public long getSize() { return size; }
    public void print(String indent) { System.out.println(indent + name + " (" + size + "B)"); }
}

public class Directory implements FileSystemNode {
    private String name;
    private List<FileSystemNode> children = new ArrayList<>();

    public void add(FileSystemNode node) { children.add(node); }

    public long getSize() {
        return children.stream().mapToLong(FileSystemNode::getSize).sum(); // recursive
    }

    public void print(String indent) {
        System.out.println(indent + name + "/");
        children.forEach(c -> c.print(indent + "  ")); // recursive
    }
}

// Usage: same interface for file and directory
Directory root = new Directory("root");
root.add(new File("CLAUDE.md", 5000));
Directory docs = new Directory("docs");
docs.add(new File("system-design-101.md", 50000));
root.add(docs);
root.getSize(); // recursively sums all files
```

## 6. Design Patterns — Behavioral

Behavioral patterns deal with how objects communicate and distribute responsibility.

### Strategy

**Define a family of algorithms, encapsulate each one, make them interchangeable. Select at runtime.**

```java
public interface SortingStrategy {
    void sort(int[] array);
}

public class QuickSort implements SortingStrategy {
    public void sort(int[] array) { /* quicksort */ }
}

public class MergeSort implements SortingStrategy {
    public void sort(int[] array) { /* mergesort */ }
}

public class Sorter {
    private SortingStrategy strategy;

    public void setStrategy(SortingStrategy strategy) {
        this.strategy = strategy;
    }

    public void sort(int[] data) {
        strategy.sort(data);  // delegate to strategy
    }
}

// Switch strategy at runtime
Sorter sorter = new Sorter();
sorter.setStrategy(data.length < 100 ? new InsertionSort() : new QuickSort());
sorter.sort(data);
```

Strategy = behavior injection. Same as passing a lambda in modern Java.

### Observer

**One-to-many dependency. When one object changes state, all its dependents are notified.**

```java
public interface EventListener<T> {
    void onEvent(T event);
}

public class EventBus {
    private final Map<Class<?>, List<EventListener<?>>> listeners = new HashMap<>();

    public <T> void subscribe(Class<T> eventType, EventListener<T> listener) {
        listeners.computeIfAbsent(eventType, k -> new ArrayList<>()).add(listener);
    }

    @SuppressWarnings("unchecked")
    public <T> void publish(T event) {
        List<EventListener<?>> eventListeners = listeners.getOrDefault(event.getClass(), List.of());
        for (EventListener<?> listener : eventListeners) {
            ((EventListener<T>) listener).onEvent(event);
        }
    }
}

// Events
public record PaymentCompletedEvent(String transactionId, double amount, String userId) {}

// Listeners
EventBus bus = new EventBus();
bus.subscribe(PaymentCompletedEvent.class, event -> emailService.sendReceipt(event));
bus.subscribe(PaymentCompletedEvent.class, event -> analyticsService.track(event));
bus.subscribe(PaymentCompletedEvent.class, event -> ledgerService.record(event));

// Publisher doesn't know about listeners
bus.publish(new PaymentCompletedEvent("TXN001", 5000.0, "user123"));
```

Java's `java.util.EventListener`, Spring's `ApplicationEventPublisher`, Kafka itself — all Observer pattern.

### Command

**Encapsulate a request as an object. Enables undo, queuing, logging of requests.**

```java
public interface Command {
    void execute();
    void undo();
}

public class TransferMoneyCommand implements Command {
    private final Account from;
    private final Account to;
    private final double amount;

    public void execute() {
        from.debit(amount);
        to.credit(amount);
    }

    public void undo() {
        to.debit(amount);
        from.credit(amount);
    }
}

public class CommandHistory {
    private final Deque<Command> history = new ArrayDeque<>();

    public void execute(Command cmd) {
        cmd.execute();
        history.push(cmd);
    }

    public void undo() {
        if (!history.isEmpty()) {
            history.pop().undo();
        }
    }
}
```

Used for: undo/redo, transaction logs, job queues (each job is a Command).

### Template Method

**Define the skeleton of an algorithm in a base class. Subclasses fill in specific steps.**

```java
public abstract class DataProcessor {
    // Template method — defines the algorithm skeleton
    public final void process() {
        readData();       // step 1
        transformData();  // step 2 — abstract, must override
        writeData();      // step 3
        sendNotification(); // step 4 — hook, optional override
    }

    protected abstract void transformData(); // must override

    protected void readData() { /* default: read from CSV */ }
    protected void writeData() { /* default: write to DB */ }
    protected void sendNotification() { /* default: no-op */ }
}

public class PayrollProcessor extends DataProcessor {
    protected void transformData() { /* apply tax, deductions */ }
    protected void sendNotification() { /* send payslips */ }
}

public class InwardRemittanceProcessor extends DataProcessor {
    protected void transformData() { /* fuzzy match beneficiary */ }
}
```

Spring's `JdbcTemplate`, `RestTemplate`, `KafkaTemplate` all use this pattern — you provide just the variable part (SQL query, callback), the template handles connection/error handling/cleanup.

### Chain of Responsibility

**Pass a request along a chain of handlers. Each handler decides to handle or pass it on.**

```java
public abstract class RequestHandler {
    private RequestHandler next;

    public RequestHandler setNext(RequestHandler next) {
        this.next = next;
        return next;
    }

    public void handle(HttpRequest request) {
        if (next != null) next.handle(request);
    }
}

public class AuthenticationHandler extends RequestHandler {
    public void handle(HttpRequest request) {
        if (!isAuthenticated(request)) {
            request.setResponse(401, "Unauthorized");
            return; // stop chain
        }
        super.handle(request); // pass to next
    }
}

public class RateLimitHandler extends RequestHandler {
    public void handle(HttpRequest request) {
        if (isRateLimited(request)) {
            request.setResponse(429, "Too Many Requests");
            return;
        }
        super.handle(request);
    }
}

public class LoggingHandler extends RequestHandler {
    public void handle(HttpRequest request) {
        log.info("Request: {}", request.getPath());
        super.handle(request); // always pass — logging doesn't block
    }
}

// Build chain
RequestHandler chain = new LoggingHandler();
chain.setNext(new AuthenticationHandler())
     .setNext(new RateLimitHandler())
     .setNext(new BusinessHandler());

chain.handle(request);
```

## 8. Clean Code and API Design Principles

### Naming

```java
// Bad: cryptic abbreviations
int d;          // what is d?
void cntFee();  // count fee? calculate fee?
String fn;      // first name? file name?

// Good: intention-revealing names
int daysUntilExpiry;
void calculateParkingFee();
String firstName;
```

**Functions should do one thing**. If you need the word "and" in the function name, split it.

```java
// Bad: does two things
void validateAndSaveUser(User user) { ... }

// Good: one thing each
void validate(User user) { ... }
void save(User user) { ... }
```

### Don't Return Null

```java
// Bad: callers must null-check everywhere
public User findById(String id) {
    return db.find(id); // might return null → NullPointerException
}

// Good: use Optional to make absence explicit
public Optional<User> findById(String id) {
    return Optional.ofNullable(db.find(id));
}

// Caller is forced to handle absence
userService.findById(id)
    .map(User::getName)
    .orElse("Unknown");
```

### Fail Fast — Validate at Boundaries

```java
public void transfer(String fromAccountId, String toAccountId, double amount) {
    // validate at the top — fail fast before any side effects
    Objects.requireNonNull(fromAccountId, "fromAccountId is required");
    Objects.requireNonNull(toAccountId, "toAccountId is required");
    if (amount <= 0) throw new IllegalArgumentException("Amount must be positive");
    if (fromAccountId.equals(toAccountId)) throw new IllegalArgumentException("Cannot transfer to same account");

    // now proceed with business logic
    Account from = accountRepository.findById(fromAccountId).orElseThrow();
    ...
}
```

### Prefer Immutability

```java
// Mutable: shared state → bugs in concurrent scenarios
public class MoneyAmount {
    public double value;
    public String currency;
}

// Immutable: safe to share across threads, no defensive copies needed
public record MoneyAmount(double value, String currency) {
    public MoneyAmount add(MoneyAmount other) {
        if (!currency.equals(other.currency)) throw new IllegalArgumentException("Currency mismatch");
        return new MoneyAmount(value + other.value, currency); // return new instance
    }
}
```

### Law of Demeter (Don't Talk to Strangers)

```java
// Bad: chaining through internals
double fee = transaction.getWallet().getAccount().getBalance().getFeeRate();
// Transaction knows about Wallet, knows about Account, knows about Balance — tight coupling

// Good: tell, don't ask
double fee = transaction.calculateFee(); // Transaction asks internally
```

### Problem 1: Parking Lot System

**Requirements**: Multi-floor parking lot. Support cars, motorcycles, trucks. Assign smallest fitting spot. Generate ticket on entry. Calculate fee on exit. Handle full lot.

**Entities**:
- `ParkingLot` — manages floors
- `ParkingFloor` — manages spots
- `ParkingSpot` — has type, status, current vehicle

```java
public enum VehicleType { MOTORCYCLE, CAR, TRUCK }

    protected VehicleType type;

}
public class Truck extends Vehicle {
    public SpotType getRequiredSpotType() { return SpotType.LARGE; }

    private final SpotType type;

        this.parkedVehicle = vehicle;
        this.status = SpotStatus.OCCUPIED;
    }

    public void unpark() {
        this.parkedVehicle = null;
        this.status = SpotStatus.FREE;
    }

    private final List<ParkingSpot> spots;

            .filter(spot -> spot.canFit(vehicle))
            .findFirst();
    }
}

public class Ticket {
    private final String ticketId;
    private final Vehicle vehicle;
    private final ParkingSpot spot;
    private final ZonedDateTime entryTime;
    private ZonedDateTime exitTime;

    public Duration getDuration() {
        ZonedDateTime exit = exitTime != null ? exitTime : ZonedDateTime.now();
        return Duration.between(entryTime, exit);
    }
}

public interface ParkingFeeStrategy {
    double calculateFee(Ticket ticket);
}

public class HourlyFeeStrategy implements ParkingFeeStrategy {
    private final double ratePerHour;
    public double calculateFee(Ticket ticket) {
        long hours = ticket.getDuration().toHours() + 1; // round up
        return hours * ratePerHour;
    }
}

public class ParkingLot {
    private final String id;
    private final List<ParkingFloor> floors;
    private final ParkingFeeStrategy feeStrategy;
    private final Map<String, Ticket> activeTickets = new ConcurrentHashMap<>();

    public Ticket parkVehicle(Vehicle vehicle) {
        ParkingSpot spot = floors.stream()
            .flatMap(f -> f.findAvailableSpot(vehicle).stream())
            .findFirst()
            .orElseThrow(() -> new RuntimeException("Parking lot is full"));

        spot.park(vehicle);
        Ticket ticket = new Ticket(UUID.randomUUID().toString(), vehicle, spot, ZonedDateTime.now());
        activeTickets.put(ticket.getTicketId(), ticket);
        return ticket;
    }

    public double unparkVehicle(String ticketId) {
        Ticket ticket = activeTickets.remove(ticketId);
        if (ticket == null) throw new IllegalArgumentException("Invalid ticket");
        ticket.setExitTime(ZonedDateTime.now());
        ticket.getSpot().unpark();
        return feeStrategy.calculateFee(ticket);
    }
}
```

- Strategy for fee calculation → easy to add weekend pricing, monthly passes
- `canFit()` on spot handles the matching logic — single responsibility
- `ConcurrentHashMap` for thread safety of active tickets
- Abstract Vehicle + SpotType enum → adding `Van` = new subclass only

### Problem 3: Elevator System

**Requirements**: N elevators, M floors. Optimal elevator assignment. Handle multiple simultaneous requests.

**Key Design**: Elevator state machine + scheduling algorithm.

```java
public enum ElevatorDirection { UP, DOWN, IDLE }
public enum ElevatorStatus { MOVING, STOPPED, MAINTENANCE }

public class ElevatorRequest {
    private final int requestedFloor;
    private final int destinationFloor;
    private final ElevatorDirection direction;
}

public class Elevator {
    private final int elevatorId;
    private int currentFloor = 1;
    private ElevatorDirection direction = ElevatorDirection.IDLE;
    private ElevatorStatus status = ElevatorStatus.STOPPED;
    private final TreeSet<Integer> upQueue = new TreeSet<>();   // floors to visit going up
    private final TreeSet<Integer> downQueue = new TreeSet<>(Collections.reverseOrder()); // floors going down

    public void addStop(int floor) {
        if (floor > currentFloor) upQueue.add(floor);
        else if (floor < currentFloor) downQueue.add(floor);
    }

    public void step() { // called every time unit
        if (direction == ElevatorDirection.UP && !upQueue.isEmpty()) {
            currentFloor++;
            if (upQueue.contains(currentFloor)) {
                upQueue.remove(currentFloor);
                openDoor();
            }
            if (upQueue.isEmpty()) direction = downQueue.isEmpty() ? ElevatorDirection.IDLE : ElevatorDirection.DOWN;
        } else if (direction == ElevatorDirection.DOWN && !downQueue.isEmpty()) {
            currentFloor--;
            if (downQueue.contains(currentFloor)) {
                downQueue.remove(currentFloor);
                openDoor();
            }
            if (downQueue.isEmpty()) direction = upQueue.isEmpty() ? ElevatorDirection.IDLE : ElevatorDirection.UP;
        }
    }

    public int distanceTo(int floor) { return Math.abs(currentFloor - floor); }
    public boolean isIdle() { return direction == ElevatorDirection.IDLE; }
    private void openDoor() { /* open door, wait, close door */ }
}

public interface ElevatorScheduler {
    Elevator selectElevator(List<Elevator> elevators, ElevatorRequest request);
}

// SCAN algorithm: assign to nearest elevator going in the same direction (or idle)
public class ScanScheduler implements ElevatorScheduler {
    public Elevator selectElevator(List<Elevator> elevators, ElevatorRequest request) {
        return elevators.stream()
            .filter(e -> e.getStatus() != ElevatorStatus.MAINTENANCE)
            .min(Comparator.comparingInt(e -> score(e, request)))
            .orElseThrow();
    }

    private int score(Elevator e, ElevatorRequest req) {
        if (e.isIdle()) return e.distanceTo(req.getRequestedFloor());
        if (e.getDirection() == req.getDirection()) return e.distanceTo(req.getRequestedFloor());
        return Integer.MAX_VALUE / 2; // penalize wrong-direction elevators
    }
}

public class ElevatorController {
    private final List<Elevator> elevators;
    private final ElevatorScheduler scheduler;

    public void handleRequest(int fromFloor, int toFloor) {
        ElevatorRequest request = new ElevatorRequest(fromFloor, toFloor,
            toFloor > fromFloor ? ElevatorDirection.UP : ElevatorDirection.DOWN);
        Elevator elevator = scheduler.selectElevator(elevators, request);
        elevator.addStop(fromFloor);
        elevator.addStop(toFloor);
    }
}
```

### Problem 4: Chess Game

**Requirements**: Two players, all piece movements, check/checkmate detection, turn management.

```java
public enum Color { WHITE, BLACK }
public enum PieceType { KING, QUEEN, ROOK, BISHOP, KNIGHT, PAWN }

public class Position {
    private final int row; // 0–7
    private final int col; // 0–7

    public boolean isValid() { return row >= 0 && row < 8 && col >= 0 && col < 8; }
    public Position offset(int dr, int dc) { return new Position(row + dr, col + dc); }
}

public abstract class Piece {
    protected final Color color;
    protected Position position;
    protected boolean hasMoved = false;

    public abstract List<Position> getValidMoves(Board board);
    public boolean canMoveTo(Position target, Board board) {
        return getValidMoves(board).contains(target);
    }
}

public class Rook extends Piece {
    @Override
    public List<Position> getValidMoves(Board board) {
        List<Position> moves = new ArrayList<>();
        // four directions: up, down, left, right
        int[][] directions = {{1,0},{-1,0},{0,1},{0,-1}};
        for (int[] dir : directions) {
            Position current = position.offset(dir[0], dir[1]);
            while (current.isValid()) {
                Piece occupant = board.getPiece(current);
                if (occupant == null) {
                    moves.add(current);
                } else {
                    if (occupant.getColor() != this.color) moves.add(current); // capture
                    break; // blocked
                }
                current = current.offset(dir[0], dir[1]);
            }
        }
        return moves;
    }
}

public class Board {
    private final Piece[][] grid = new Piece[8][8];

    public Piece getPiece(Position pos) { return grid[pos.getRow()][pos.getCol()]; }
    public void setPiece(Position pos, Piece piece) { grid[pos.getRow()][pos.getCol()] = piece; }
    public void movePiece(Position from, Position to) {
        Piece piece = getPiece(from);
        setPiece(to, piece);
        setPiece(from, null);
        piece.setPosition(to);
        piece.setHasMoved(true);
    }
}

public class Game {
    private final Board board;
    private final Player whitePlayer;
    private final Player blackPlayer;
    private Color currentTurn = Color.WHITE;
    private GameStatus status = GameStatus.IN_PROGRESS;

    public MoveResult makeMove(Player player, Position from, Position to) {
        if (getPlayerColor(player) != currentTurn) return MoveResult.WRONG_TURN;

        Piece piece = board.getPiece(from);
        if (piece == null || piece.getColor() != currentTurn) return MoveResult.INVALID_PIECE;
        if (!piece.canMoveTo(to, board)) return MoveResult.INVALID_MOVE;

        // execute move
        board.movePiece(from, to);

        // check if own king is now in check (illegal)
        if (isInCheck(currentTurn)) {
            board.undoMove(from, to); // revert
            return MoveResult.LEAVES_KING_IN_CHECK;
        }

        // switch turns
        currentTurn = currentTurn == Color.WHITE ? Color.BLACK : Color.WHITE;

        // check win conditions
        if (isCheckmate(currentTurn)) status = GameStatus.CHECKMATE;
        else if (isStalemate(currentTurn)) status = GameStatus.STALEMATE;

        return MoveResult.SUCCESS;
    }

    private boolean isInCheck(Color color) {
        Position kingPos = findKing(color);
        return getAllPieces(color.opponent()).stream()
            .anyMatch(piece -> piece.canMoveTo(kingPos, board));
    }

    private boolean isCheckmate(Color color) {
        if (!isInCheck(color)) return false;
        return getAllPieces(color).stream()
            .allMatch(piece -> piece.getValidMoves(board).stream()
                .noneMatch(move -> !wouldLeaveKingInCheck(piece, move, color)));
    }
}
```

### Problem 6: Rate Limiter (LLD)

**Requirements**: Limit requests per user per time window. Thread-safe. Pluggable algorithm.

```java
public interface RateLimiter {
    boolean allowRequest(String userId);
}

// Token Bucket implementation
public class TokenBucketRateLimiter implements RateLimiter {
    private final int capacity;
    private final double refillRatePerSecond;
    private final Map<String, Bucket> buckets = new ConcurrentHashMap<>();

    public boolean allowRequest(String userId) {
        Bucket bucket = buckets.computeIfAbsent(userId, k -> new Bucket(capacity));
        return bucket.tryConsume();
    }

    private class Bucket {
        private double tokens;
        private long lastRefillTimestamp;

        synchronized Bucket(int initialTokens) {
            this.tokens = initialTokens;
            this.lastRefillTimestamp = System.currentTimeMillis();
        }

        synchronized boolean tryConsume() {
            refill();
            if (tokens >= 1) {
                tokens--;
                return true;
            }
            return false;
        }

        private void refill() {
            long now = System.currentTimeMillis();
            double elapsed = (now - lastRefillTimestamp) / 1000.0;
            tokens = Math.min(capacity, tokens + elapsed * refillRatePerSecond);
            lastRefillTimestamp = now;
        }
    }
}

// Sliding Window Log implementation
public class SlidingWindowLogRateLimiter implements RateLimiter {
    private final int maxRequests;
    private final long windowMillis;
    private final Map<String, Deque<Long>> userTimestamps = new ConcurrentHashMap<>();

    public boolean allowRequest(String userId) {
        long now = System.currentTimeMillis();
        Deque<Long> timestamps = userTimestamps.computeIfAbsent(userId, k -> new ArrayDeque<>());

        synchronized (timestamps) {
            // remove entries outside window
            while (!timestamps.isEmpty() && timestamps.peekFirst() < now - windowMillis) {
                timestamps.pollFirst();
            }
            if (timestamps.size() < maxRequests) {
                timestamps.addLast(now);
                return true;
            }
            return false;
        }
    }
}

// Factory to select algorithm
public class RateLimiterFactory {
    public static RateLimiter create(String algorithm, int limit, long windowMs) {
        return switch (algorithm) {
            case "TOKEN_BUCKET" -> new TokenBucketRateLimiter(limit, limit / (windowMs / 1000.0));
            case "SLIDING_WINDOW" -> new SlidingWindowLogRateLimiter(limit, windowMs);
            default -> throw new IllegalArgumentException("Unknown algorithm: " + algorithm);
        };
    }
}
```

```java
public class CardInsertedState implements ATMState {

        if (atm.getCurrentCard().validatePin(pin)) {
            atm.setState(new AuthenticatedState());
            atm.display("Authentication successful. Select amount.");
        } else {
            pinAttempts++;
            if (pinAttempts >= 3) {
                atm.display("Card blocked. Ejecting card.");

        }

    }

public class CashDispenser {
    private final Map<Integer, Integer> denominations; // denomination → count

    public CashDispenser() {
        denominations = new TreeMap<>(Collections.reverseOrder());
        denominations.put(2000, 10);
        denominations.put(500, 20);
        denominations.put(200, 30);
        denominations.put(100, 50);
    }

    public Map<Integer, Integer> dispense(int amount) {
        Map<Integer, Integer> dispensed = new LinkedHashMap<>();
        int remaining = amount;

        for (Map.Entry<Integer, Integer> entry : denominations.entrySet()) {
            int denom = entry.getKey();
            int available = entry.getValue();
            int needed = Math.min(remaining / denom, available);
            if (needed > 0) {
                dispensed.put(denom, needed);
                remaining -= needed * denom;
                denominations.put(denom, available - needed);
            }
        }

        if (remaining > 0) throw new InsufficientCashException("ATM cannot dispense exact amount");
        return dispensed;
    }

    public boolean hasCash(int amount) {
        // simulate without modifying state
        int remaining = amount;
        for (Map.Entry<Integer, Integer> entry : denominations.entrySet()) {
            int denom = entry.getKey();
            remaining -= Math.min(remaining / denom, entry.getValue()) * denom;
        }
        return remaining == 0;
    }
}
```

### Problem 8: Splitwise / Expense Sharing

**Requirements**: Add expenses, split equally/percentage/exact, show balances, simplify debts.

```java
public abstract class SplitStrategy {
    public abstract Map<User, Double> split(double amount, List<User> participants);
}

public class EqualSplit extends SplitStrategy {
    public Map<User, Double> split(double amount, List<User> participants) {
        double share = amount / participants.size();
        return participants.stream().collect(Collectors.toMap(u -> u, u -> share));
    }
}

public class PercentageSplit extends SplitStrategy {
    private final Map<User, Double> percentages; // user → percentage

    public Map<User, Double> split(double amount, List<User> participants) {
        double total = percentages.values().stream().mapToDouble(Double::doubleValue).sum();
        if (Math.abs(total - 100.0) > 0.01) throw new IllegalArgumentException("Percentages must sum to 100");
        return percentages.entrySet().stream()
            .collect(Collectors.toMap(Map.Entry::getKey, e -> amount * e.getValue() / 100));
    }
}

public class ExactSplit extends SplitStrategy {
    private final Map<User, Double> exactAmounts;

    public Map<User, Double> split(double amount, List<User> participants) {
        double total = exactAmounts.values().stream().mapToDouble(Double::doubleValue).sum();
        if (Math.abs(total - amount) > 0.01) throw new IllegalArgumentException("Amounts don't add up");
        return exactAmounts;
    }
}

public class Expense {
    private final String expenseId;
    private final User paidBy;
    private final double amount;
    private final String description;
    private final Map<User, Double> splits; // who owes how much
}

public class ExpenseManager {
    // balance[A][B] = amount A owes B (negative means B owes A)
    private final Map<User, Map<User, Double>> balances = new HashMap<>();

    public void addExpense(Expense expense) {
        User payer = expense.getPaidBy();
        expense.getSplits().forEach((user, share) -> {
            if (!user.equals(payer)) {
                // user owes payer
                adjustBalance(user, payer, share);
            }
        });
    }

    private void adjustBalance(User debtor, User creditor, double amount) {
        balances.computeIfAbsent(debtor, k -> new HashMap<>())
                .merge(creditor, amount, Double::sum);
        balances.computeIfAbsent(creditor, k -> new HashMap<>())
                .merge(debtor, -amount, Double::sum);
    }

    // Simplify debts: minimize number of transactions
    public List<Transaction> simplifyDebts() {
        // Compute net balance for each user
        Map<User, Double> netBalance = new HashMap<>();
        balances.forEach((user, debts) ->
            debts.forEach((other, amount) ->
                netBalance.merge(user, amount, Double::sum)));

        List<User> creditors = netBalance.entrySet().stream()
            .filter(e -> e.getValue() > 0)
            .sorted(Map.Entry.<User, Double>comparingByValue().reversed())
            .map(Map.Entry::getKey).collect(Collectors.toList());

        List<User> debtors = netBalance.entrySet().stream()
            .filter(e -> e.getValue() < 0)
            .sorted(Map.Entry.comparingByValue())
            .map(Map.Entry::getKey).collect(Collectors.toList());

        List<Transaction> transactions = new ArrayList<>();
        int i = 0, j = 0;
        while (i < creditors.size() && j < debtors.size()) {
            User creditor = creditors.get(i);
            User debtor = debtors.get(j);
            double amount = Math.min(netBalance.get(creditor), -netBalance.get(debtor));
            transactions.add(new Transaction(debtor, creditor, amount));
            netBalance.merge(creditor, -amount, Double::sum);
            netBalance.merge(debtor, amount, Double::sum);
            if (netBalance.get(creditor) == 0) i++;
            if (netBalance.get(debtor) == 0) j++;
        }
        return transactions;
    }
}
```

## 10. Common Mistakes in LLD Interviews

**1. God class**: One class that does everything. Apply SRP aggressively.

**2. Anemic domain model**: Classes that are just data bags (getters/setters), all logic in service classes. Move behavior to where the data lives.
```java
// Anemic: service decides if order can be cancelled
orderService.canCancel(order); // service knows order internals

// Rich domain model: order knows its own rules
order.cancel(); // order validates and changes its own state
```

**3. Premature inheritance**: Using inheritance when composition would be cleaner.

**4. Not using enums for states**: If/else chains on string status fields → use enums, then State pattern.

**5. Skipping interfaces**: Writing concrete classes everywhere makes testing and extending impossible.

**6. Ignoring thread safety**: Interviewers ask "is this thread safe?" Know when to use `synchronized`, `ConcurrentHashMap`, `AtomicInteger`.

**7. No validation**: Don't assume valid input. Validate at object boundaries.

**8. Not modeling state transitions**: Every entity with a status field has a state machine. Draw it out. Show invalid transitions.

**9. Too much UML, too little code**: Diagrams without code is design without execution. Write the key classes in full.

**10. Not asking clarifying questions**: Jumping to solution before understanding scope. Always spend 5 min on requirements.
