4. KEY ARCHITECTURAL DECISIONS
================================================================================

LEDGER-SERVICE:
  1. Multi-Module Architecture: API + Worker + Base separation for clean concerns
     - API module handles REST endpoints
     - Worker module handles async Kafka consumers
     - Base module contains shared domain, configs, and utilities
  2. Kafka as Event Backbone: Used Kafka for transaction sync, delay queues,
     and inter-service communication
  3. ZSTD Compression: Chose ZSTD over default compression for Kafka producers
     (better compression ratio for transaction data)
  4. Redis for Caching: Redisson client for distributed caching/locking
  5. Resilience4j: Circuit breaker pattern for external service calls
  6. JWT Security: Custom security filter chain with JWT validation
  7. Retrofit for Service-to-Service: Type-safe HTTP clients for internal APIs
  8. Google JIB: Containerization without Docker daemon (faster CI builds)
  9. Facets Migration: Moved from direct K8s deployment to Facets platform
  10. OpenTelemetry: Adopted OTel standard for distributed tracing
  11. Standalone Redis in UAT: Cost optimization for non-prod environments
  12. Secrets Externalization: Moved from config-file secrets to external vault

OA-LENDING-OFFERS-SERVICE:
  1. Greenfield Spring Boot 3: Started fresh with latest framework (no legacy)
  2. MongoDB for Loan Data: Document store for flexible loan offer schemas
  3. S3 for File Storage: CSV offer files stored in S3, processed on-demand
  4. Retrofit Singleton: HTTP client as singleton for connection pooling
  5. CSV Domain Separation: Separated CSV field names from domain models
  6. SSE for Real-Time: Server-Sent Events for consent capture flow
  7. Kafka for Events: Event-driven consent and offer processing
  8. ModelMapper: Chose ModelMapper over MapStruct for simpler DTO mapping
  9. Spotify Docker Plugin + JIB: Dual containerization support
  10. Environment-Specific S3 Keys: Separate AWS configs per environment
