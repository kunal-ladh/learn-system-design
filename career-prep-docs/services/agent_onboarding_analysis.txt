2. TECH STACK
================================================================================

Language & Framework:
  - Java 17
  - Spring Boot 3.x (upgraded from 3.3.x → 3.5.11 LTS over time)
  - Spring Security (JWT-based auth with custom AuthenticationFilter)
  - Spring Kafka (event-driven architecture)
  - Spring Data MongoDB
  - Spring Retry
  - Spring Cache
  - Spring Integration

Database:
  - MongoDB (primary data store)
  - Collections: Agent, ActivityLog, AgentSequence, Distributor, KycResponse,
    DigioEsignResponse, SimBindingInfo

Messaging & Event Streaming:
  - Apache Kafka (internal + external topics, batch processing, zstd compression)
  - AWS SQS (cron-based worker processing)

Cloud & Infrastructure:
  - AWS S3 (document storage)
  - AWS Secrets Manager (secrets management)
  - AWS STS (OIDC-based authentication)
  - AWS ECR (container registry)
  - Kubernetes (deployment target, readiness/liveness probes)
  - Facets Cloud (deployment orchestration — migrated from raw K8s)
  - Datadog (APM, dd-java-agent integration)
  - Bitbucket Pipelines (CI/CD)

API & Integration Libraries:
  - Retrofit 2.11 + OkHttp 4.12 (HTTP client for external service calls)
  - Jackson (JSON serialization/deserialization)
  - ModelMapper + MapStruct (object mapping)
  - Apache PDFBox (PDF generation for BGV reports)
  - JJWT 0.12.3 (JWT token generation and validation)
  - SpringDoc OpenAPI (Swagger UI documentation)
  - Logstash Logback Encoder (structured logging)
  - Guava, Apache Commons (Lang3, Collections4, Text, IO)
  - SonarQube Scanner (code quality)

External Service Integrations (via Retrofit clients):
  - IAM Service (user creation, employee ID generation, permissions)
  - Digio API (eSign, face match verification)
  - Risk Engine API (agent risk assessment)
  - Notification Service (OTP via SMS/email)
  - PII Vault API (sensitive data storage)
  - PDF Converter API (document conversion)
  - Long Codes API (agent code management)
  - Civic Data Hub API (civic data verification)
  - NSDL PB Customer Service (banking operations, penny drop)

Architecture Pattern:
  - Multi-channel controller layer: /ag (agent-facing), /app (mobile app),
    /wb (web backoffice) — clean separation of concerns
  - Service-DAO-Repository layered architecture
  - Worker pattern for async processing (Kafka + SQS workers)
  - Async helpers for non-blocking notification dispatch

4. KEY ARCHITECTURAL DECISIONS
================================================================================

4.1 Multi-Channel Controller Architecture
  - Separated controllers into /ag (agent-facing), /app (mobile app), and
    /wb (web backoffice) packages
  - Each channel has its own set of controllers with appropriate permissions
  - Enables independent API evolution per channel

4.2 Event-Driven Architecture with Kafka
  - Internal Kafka topics for intra-service async processing
  - External Kafka topics for cross-service communication
  - Worker pattern (NewAgentOnboardingWorker, OnboardingActivityWorker) for
    consuming and processing messages
  - Batch processing with parallelized publishing for throughput
  - Migrated compression from default to zstd for better performance

4.3 JWT-Based Authentication with Custom Security Filter
  - Custom AuthenticationFilter, AuthenticationToken, NiyoAuthenticationProvider
  - SkipPathRequestMatcher for whitelisting public endpoints
  - AgentAuthenticationEntryPoint for custom error responses
  - Separated authentication config to resolve circular dependency

4.4 AWS Secrets Manager for Secrets Management
  - Migrated from hardcoded/config-file secrets to AWS Secrets Manager
  - AwsSecretManagerInfoRegistry for centralized secret loading
  - Kafka credentials, API keys, and sensitive configs all from ASM

4.5 Retrofit-Based API Client Pattern
  - RetrofitConfig for centralized HTTP client configuration
  - Dedicated ApiClientService classes for each external service
  - Clean separation between API client layer and business logic

4.6 MongoDB with DAO Pattern
  - DAO layer (AgentDAOService, ActivityLogDAOService, etc.) between
    service and repository layers
  - Compound indexing optimization for frequently queried fields
  - AgentSequence collection for auto-incrementing agent codes

4.7 Facets Cloud Migration (from raw Kubernetes)
  - Migrated from raw K8s YAML deployments to Facets Cloud orchestration
  - Deleted legacy kube files, updated pipeline for Facets deployment
  - Separate UAT and PROD deployment steps with manual triggers

4.8 HTML Template-Based PDF Generation
  - BGV reports generated from HTML templates with dynamic field injection
  - Agent registration documents as HTML templates
  - Terms & Conditions templates (CAT_A, CAT_B) as static HTML
  - PDFBox for HTML-to-PDF conversion

4.9 Structured Logging & Observability
  - Logstash Logback Encoder for JSON-structured logs
  - MDCFilter and MDCTaskDecorator for request context propagation
  - Datadog Java agent integration for APM
  - Separate metrics port (8081) for readiness/liveness probes
