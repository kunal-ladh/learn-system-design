SECTION 4: KEY ARCHITECTURAL DECISIONS
================================================================================

1. Multi-Module Architecture (niyo-nsdl-pb-customer-service)
   - Separated into application, commons, services, and worker modules
   - API and Worker deployed as separate containers on Kubernetes
   - Enables independent scaling of API vs background processing

2. Lambda-to-Kubernetes Migration
   - Originally built as AWS Lambda (nsdl-pb-customer-service)
   - Migrated to Kubernetes via Facets Cloud (niyo-nsdl-pb-customer-service)
   - Both versions maintained in parallel during transition
   - Lambda version kept for specific use cases (S2S callbacks, SQS processing)

3. Facets Cloud Adoption (BHAR-566)
   - Migrated from direct K8s/Lambda deployments to Facets Cloud platform
   - Used facetsctl CLI for deployment automation
   - Separate Facets services: niyo-nsdl-cs-api and niyo-nsdl-cs-worker
   - Google JIB for multi-arch container builds (amd64 + arm64)

4. Event-Driven Architecture
   - Kafka for async messaging between services
   - SQS for Lambda-based queue processing
   - EventBridge for scheduled cron jobs
   - S2S callback APIs for bank-to-service communication

5. Security Architecture
   - AWS Secrets Manager for all sensitive credentials
   - KMS encryption for secrets at rest
   - MongoDB field-level encryption (mongodb-crypt)
   - IP-whitelisted callback API Gateway for NSDL bank callbacks
   - VPC-attached Lambdas for network isolation
   - Private API Gateway endpoints with VPC endpoint policies
   - Git secret scanning enforcement

6. Database Design
   - MongoDB with compound indexes (createdDate + corporateCode, createdDate + internally-synced)
   - PII Vault integration for sensitive customer data (Aadhaar, etc.)
   - Schema versioning (PII vault schema version 2.0)

7. Kafka Configuration
   - Migrated Kafka clusters (UAT migration)
   - Changed compression algorithm from default to ZSTD for better throughput
   - Separated common Kafka config from environment-specific config
   - Added retry logic to Kafka publisher
   - Fixed consumer configuration to prevent missed messages

8. Lambda SnapStart
   - Enabled Lambda SnapStart for nsdl-pb-customer-service
   - Reduces cold start latency for Java Lambda functions
   - Critical for 7GB memory Lambda functions

9. Distroless Base Images
   - Using gcr.io/distroless/java17-debian12 for minimal attack surface
   - Custom base images from ECR (java-17-multiarch-non-root)
